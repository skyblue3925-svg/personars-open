# 양적연구 고도화 계획

## 목표

현재 양적연구는 문항별 평균, 4점 이상 응답 비율, 응답 분포, 집단별 평균 비교를 제공한다. 다음 단계에서는 학생이 “숫자를 읽는 법”을 배우도록 측정 설계, 표본 설계, 집단 비교, 해석 제한을 더 명확히 만든다.

## 방법론 전환

지금 방식은 생성된 응답을 요약하는 데 가깝다. 고도화 후에는 다음 흐름으로 바꾼다.

1. 개념 정의
   - 독립변인, 종속변인, 통제/맥락 변인을 학생이 확인한다.
   - 각 변인이 어떤 문항으로 측정되는지 명시한다.

2. 척도 설계
   - 단일 문항 평균이 아니라 변인별 복합 지표를 만든다.
   - 예: `종속변인 점수 = q1, q4 평균`, `독립변인 점수 = q2, q5 평균`.
   - 역문항을 추가할 수 있게 하고, 역코딩 여부를 표시한다.

3. 모집단과 표본 구분
   - 모집단: 연구가 설명하려는 전체 범위
   - 표본: 실제 응답을 생성한 집단 구성
   - 보고서에는 “이 표본으로 말할 수 있는 것 / 말할 수 없는 것”을 분리해서 표시한다.

4. 집단 비교
   - 단순 평균표 대신 다음 지표를 함께 제공한다.
   - 집단별 평균 차이
   - 가장 차이가 큰 문항
   - 변인별 집단 차이
   - 표본 수가 작은 집단에 대한 해석 경고

5. 가설 판정
   - `지지`, `부분 지지`, `지지 어려움`을 자동 판정하되, 근거 문장을 함께 보여준다.
   - 예: “학생 집단의 종속변인 평균은 높지만 독립변인 점수와 일관된 관계가 약해 부분 지지로 해석한다.”

6. 해석 경고
   - 인과관계 과장 경고
   - 표본 대표성 경고
   - 문항 유도성 경고
   - 시뮬레이션 자료 일반화 금지 경고

## 구현 단위

### 1. 타입 확장

- `ScaleDirection = 'positive' | 'reverse'`
- `SurveyQuestion.measureId`
- `MeasureDefinition`
  - `id`
  - `label`
  - `role: independent | dependent | context`
  - `questionIds`
  - `interpretationGuide`
- `HypothesisEvaluation`
  - `status: support | partial | not-support`
  - `evidence`
  - `warnings`

### 2. 설문 설계 UI

- 문항별 변인 배정 UI 추가
- 역문항 토글 추가
- 변인별 포함 문항 수 표시
- 종속변인 문항이 2개 미만이면 경고

### 3. 분석 엔진

- `buildMeasureScores(project)`
- `compareGroupsByMeasure(project)`
- `findLargestGroupDifference(project)`
- `evaluateHypothesis(project)`
- `buildInterpretationWarnings(project)`

### 4. 결과 화면

- 문항별 요약보다 변인별 요약을 위에 배치
- 집단별 변인 점수 비교표 추가
- “가설 판정” 패널 추가
- “해석 주의” 패널 추가

### 5. 보고서

- 양적 분석 섹션을 다음 구조로 변경
  - 측정 설계
  - 변인별 점수
  - 집단 비교
  - 가설 판정
  - 해석 제한

## 테스트 기준

- 역문항이 올바르게 역코딩된다.
- 변인별 점수가 포함 문항 평균으로 계산된다.
- 집단별 비교가 표본 수와 평균 차이를 함께 반환한다.
- 표본 수가 작은 집단에는 해석 경고가 붙는다.
- 보고서에 모집단, 표본, 가설 판정, 해석 제한이 모두 포함된다.

## 배포 고려

- 모든 계산은 브라우저에서 동작하는 순수 TypeScript 함수로 유지한다.
- 외부 API 없이 `npm run build` 결과물만으로 정적 배포가 가능해야 한다.
- 추후 실제 LLM/API를 붙이더라도 양적 계산 엔진은 서버 의존 없이 독립적으로 검증 가능하게 둔다.
